# OpenDocument presentation support

> **Last reviewed:** 2026-10-16 · **Last updated:** 2026-10-16 · **Status:** partial ODF conversion; supported table formulas, number formats, ordered nested tables, advanced comments and structured-notes PPTX projections are implemented. Final integrated validation passed; complete ODF and external-consumer fidelity remain open.

DeckCraft reads and writes editable ODP presentations using the public OASIS OpenDocument 1.3
format. This is broad conversion support, not complete ODF compatibility or lossless interchange.

Open an `.odp` through File → Open, Finder, drag and drop, the browser file picker, CLI or MCP.
Save As and Export offer OpenDocument. File commands accept `format: "odp"`, including
`file.openBytes` / `file.saveBytes` for browser hosts. For example:

```sh
deckcraft-cli convert input.pptx output.odp
deckcraft-cli convert input.odp output.pptx
```

ODP files open as copies with a conversion notice and available import warnings. Save asks for a
destination. After an explicit Save As, subsequent saves use the chosen file. Every ODP import
retains the exact source archive as a recovery resource in the native document. Recovery bytes
are not editable ODF support and are not substituted for the edited presentation on ODP export.
File → Info → Recover ODP saves the exact original package, without DeckCraft edits. This also works after saving and reopening a native document. Automation uses `file.exportSource` with a destination path, or `file.sourceBytes` for a base64 response (limited to 11 MiB before encoding). Keep the original and review the conversion before replacing it.

## Editable content

- Slide order, names, dimensions, hidden slides, solid/gradient/image backgrounds.
- Text frames, inherited paragraph/run styles, script fonts and independent Asian/complex-script size, weight, slant and language, percentage font sizes, common decorations/highlights, alignment, insets, tabs, line breaks, fields and hyperlinks. Numbered/bulleted lists preserve nested levels, continuations and explicit restarts. Links in notes and table cells resolve to slides. Paragraph-area opaque solid colors and explicit no-fill overrides remain separate from character highlights, including a narrowly recognized LibreOffice paragraph graphic-property wrapper. Empty paragraphs paint a line area; wrapped lines fill the paragraph column between its margins, excluding paragraph spacing. Exact typography and external-viewer coverage can differ.
- Explicit Normal and absolute minimum paragraph line heights persist through native/ODP, layout, commands and the Paragraph dialog. Latin paragraph typing font/size defaults retain their own owner. Additional/mixed line-height semantics remain constrained; a dormant local notes modifier disabled by shared Normal is retained in source and blocks edited export until its inheritance ownership is represented. Core PPTX export refuses the new line policies pending a verified mapping.
- Rectangles, ellipses, lines, connectors, preset outlines, SVG paths, polygons and a bounded
  subset of enhanced geometry formulas with Unicode guide names and elliptical/quadrant path commands; affine transforms, mirrors and nested groups. Explicit text areas are admitted only when their full-frame geometry matches the native text box; custom areas remain guarded.
- Solid/gradient/image fills, affine linear and circular radial gradients, unflipped bitmap tile dimensions/alignment/offsets, common outlines, simple shadows, embedded pictures, crop and selected picture adjustments. Some picture adjustments are baked into exported image bytes.
- Native tables, inherited cell fonts/defaults, relative widths, row sizes, repeated/merged cells, dashed/double/diagonal borders and vertical alignment. Stored strings, Booleans, exact numeric/percentage/currency and bounded temporal constants keep separate rich display authority. Versioned formulas include bounded decimal division/powers, functions, ranges and reference rewriting; formats and ordered nested tables have commands and UI editors. Native/ODP persistence and editable PPTX table/group projections with verified typed metadata cover the explicit [supported profiles](table-data.md). Functions/settings outside that catalog remain open; checked pencil/eraser operations preserve formulas and ordered content.
- Embedded chart import includes category, scatter and bubble data domains, mixed series, secondary axes, common axis formats/scales, point styles, regressions and error indicators where represented by the model. Export supports scatter/bubble domains, compatible combination series, secondary axes, common formats, point styles, regressions and error indicators. Remaining unrepresented settings refuse.
- Structured notes pages retain native sizes, associated notes masters, shared defaults, graphics, fields and live owning-slide previews. Notes Page, Notes Master and PDF use that structure; note text remains one editable body. PPTX materializes editable pages using one core notes master/size and verified typed metadata for native sharing, unused masters and per-page dimensions. Structured-notes comparison remains guarded; see [interchange contracts](table-data.md#odp-and-pptx-representations).
- Comments retain independent creation timestamps, authored display-date labels and initials without invented dates. Stable identities, three statuses, nested replies, rich bodies, Unicode-scalar ranges, tasks and actual-file attachments have commands, rich UI and native/ODP/PPTX persistence. Supported transfer/comparison preserves their dependency closure. PPTX core shape anchors plus verified native range metadata do not establish foreign Office character-position equivalence. Unknown rich source semantics warn and retain source; see [advanced comments](table-data.md#advanced-comments).
- A native SMIL subset for transitions and animation timing, including supported effects, triggers, ordering, concurrent groups, repeat/rewind/easing, advance clocks and embedded transition sounds. Complex graphs and unsupported semantics warn and retain source data.
- Native indefinitely repeating trigger steps hold their dependent groups until an explicit click advances them; rewind and replay retain that scheduling. External repeated-trigger SMIL mapping and consumer playback remain unverified.
- Named/default/automatic styles and shared regular master artwork/backgrounds in the supported structural subset. Pages naming the same source master share one editable owner through native and ODP roundtrips. Explicit page paint stays local even when it equals the master paint. Presentation placeholders and broader inherited defaults remain constrained; legacy/default native layouts can still export flattened artwork.
- Presentation-template resources retain independent names, labels, ordered role/box slots, unused definitions and selected page references through native and ODP persistence. `presentation.template.*` commands edit resources; `slide.presentationTemplate` selects a resource without placing, moving or restyling page objects. Template application and live placeholder/style inheritance remain open. Core PPTX export refuses these resources until a mapping exists.

Whole-slide copy/reuse and selected-template comparison transfer the selected template-resource closure under fresh identities, preserving shared owners and stored geometry. Comparison refuses unused template-resource revisions until it has document-resource changes. The native whole-slide clipboard/cut/paste/reuse lane transfers a bounded selected notes-page/master/media closure under fresh IDs for its strict supported subset, including real named and legacy notes owners. Source and destination global text/header-footer defaults must match and be dependency-free; embedded fonts are excluded. The admitted shape subset is strict. ODP provenance/source-loss warnings and unsupported Tables, Charts, raw extensions and other unclosed dependencies cannot obtain a cross-document receipt; same-UID valid unsupported content remains usable. Comparison/diff/adopt/accept still refuse structured notes, including deletion-only changes. Same-document operations retain the guard and validate current named masters/body references; implicit fallback follows the current master. Explicit text or rendered-picture extraction remains available. These safeguards do not establish full cross-document fidelity.

## Remaining limits

Complete ODF semantics are not implemented. Open work includes custom text areas and active enhanced-geometry stretch points, text stretching and minimum-size constraints, arbitrary markers/effects, elliptical/repeating gradients, flipped/staggered tiles, rare typography and advanced paragraph backgrounds (images, nonopaque paint, gradients, padding/borders/joined areas and mixed-encoding inheritance conflicts), additional/mixed line heights and dormant notes-modifier ownership, formula functions/settings and formats outside the [supported catalog](table-data.md), complete chart export, unrepresented notes structures and guarded structured-notes comparison, live regular placeholder/style inheritance and template application. Painted paragraph backgrounds have no verified interoperable DrawingML mapping, so core PPTX/POTX/PPSX export refuses them. Conflicting painted standard/extension background declarations across style ancestors are rejected while their precedence remains unverified. Paragraph-local list restarts are supported in native/ODP documents; the app refuses PPTX/POTX/PPSX export containing these restarts until their OOXML mapping is implemented.

Arbitrary timing graphs, unsupported presets, repeated triggers and transformed motion paths remain constrained. Native external-viewer playback has not established full slideshow compatibility. Embedded spreadsheet/application editing and package-preserving edits to arbitrary extensions are unfinished. Codec support determines media playback.

Unsupported drawing objects can become opaque placeholders. Their diagnostic XML keeps lexical content and in-scope namespaces within cumulative resource budgets. Unmapped XML names/attributes in content, styles and embedded objects produce warnings. Recognizing the LibreOffice namespace for parsing does not authorize its other elements or attributes: the extension exception checks the exact paragraph-style context, supported fill values and empty child structure. A bounded semantic audit also checks paragraph/text property bags, including unused definitions. Coverage is incomplete for other standard structures, so a successful import/export is not proof of lossless interchange.

Normal regenerated export refuses reported import limitations, unresolved opaque objects and explicitly unsupported model settings before writing a destination. A narrowly checked source-preserving path supports plain local slide-text edits when the existing paragraph/text audit is eligible and any additional gamma warning has a fresh bounded source proof: it proves every other model property unchanged, patches only owned text ranges, retains every untouched XML byte and package member payload, and reimports the rebuilt result. Bounded ZIP32 descriptors are verified against physical record boundaries, sizes and CRCs. A narrow profile permits empty configuration directories; configuration files remain refused. A closed cache profile can discard a verified unreferenced standard PNG thumbnail and stale optional text-count attributes, retaining structural counts and every other XML byte. Its optional standard root-owner version must match the manifest and every admitted fixed XML root; nonroot owners keep the exact two-attribute restriction. Schema-valid empty settings documents may omit the settings child, while configuration entries remain unsupported. A standard empty scripts container is admitted only as the first and unique direct content-root child, with no attributes or element children and XML whitespace only. Script content and listeners remain refused. Font declarations retain standard generic-family/pitch enums and bounded opaque font names with exact typed references; these opaque keys do not relax general style/resource IDs, resource paths or font-family syntax. Six exact drawing-page visibility switches and the graphic controls `draw:auto-grow-height`, false-only `draw:fit-to-size`, `style:shrink-to-fit`, `fo:wrap-option`, `fo:min-height` and `fo:min-width` can be retained without changing their bytes. Stretching and nonstandard fit spellings remain refused; minimum dimensions are retained source constraints, not native size enforcement. Geometry or saved fitting-scale changes still refuse text-only preservation. Exact neutral color-channel/mirror values and mapped image opacity, luminance, contrast and color modes can remain unchanged in the closed profile. Whole auto clipping and four canonical zero edge lengths are admitted as identities; nonzero clipping remains outside that profile. Bounded gamma percentages can be retained unchanged under a separate source-only proof, without interpreting their value or calling any value an identity. Every detected gamma instruction gets a distinct native-fidelity warning. A gamma-only document still refuses edited export because the old eligible passive-text audit remains required. Invalid gamma owners/values also refuse on the no-cache preservation route. Older saved native documents lacking the reconstructed warning or provenance fail before interchange regeneration. Unsupported standard frame protection receives its own blocking diagnostic, including on notes previews and unused definitions. It is never mapped to the single native lock bit or admitted by the preservation profile; prior passive preservation routes also refuse it. Fresh retained-source checks protect older native documents that lack the diagnostic. A bounded historical creation timestamp may be retained exactly; modification-date claims remain refused until an explicit policy exists. Unknown counters, unproven dependencies and other previews/statistics refuse. Other exclusions include ZIP64, opaque parts, active/external content, complex text and non-text edits. It never returns the untouched original as an edited export. PPTX conversion also refuses reported retained ODP limitations. The original archive remains recoverable; no exporter substitutes that archive for the edited document. Native DeckCraft save retains both the editable conversion and source recovery data.

External resources are never downloaded. Password-protected packages, unsafe package paths,
mixed slide dimensions and inputs exceeding resource limits are rejected.

## Verification and implementation

Contributor-authored tests cover rich text, lists, media, shapes/groups/transforms, gradients,
custom geometry, merged tables, embedded charts, metadata, comments, notes, source recovery and
hostile-input budgets. Further independent regressions cover namespace allocation amplification, foreign-content reporting, timing schedule/audio constraints, actual renderer list numbering and enhanced-path equivalence. Independent compatibility tests and generated XML are checked against the
public OASIS ODF 1.3 RelaxNG schema. These checks establish the tested mappings and XML validity;
they do not establish full compatibility with LibreOffice or PowerPoint rendering.

The local macOS build was also tested opening a real ten-slide PPTX from Finder while running
and during launch. Matching private PPTX/ODP files are tested locally and are never repository
fixtures. No private text or media is published.

`crates/odp` maps ODF objects directly to the presentation model. ZIP entries, decompressed bytes,
XML depth/elements/attributes, expanded tables/text/chart data, style inheritance and formulas are
bounded. Native constant metadata is validated across every owner before structural repair; stale values are cleared with a load diagnostic. Typed merged grids require exact nonoverlapping ownership. Native JSON has pre-parse token/work/metadata limits and a capped writer; these are input limits, not process-memory guarantees. Import never extracts linked paths to disk. Namespace matching uses namespace URIs.
The MIME entry is first, uncompressed and without extra fields; exported XML/media have manifest
records. The macOS bundle registers document types and receives queued native open events.

Standards: [ODF 1.3 Part 2: Packages](https://docs.oasis-open.org/office/OpenDocument/v1.3/os/part2-packages/OpenDocument-v1.3-os-part2-packages.html)
and [Part 3: Schema](https://docs.oasis-open.org/office/OpenDocument/v1.3/os/part3-schema/OpenDocument-v1.3-os-part3-schema.html).
